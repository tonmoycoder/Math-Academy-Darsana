# AGENTS.md — rules for any coding agent working on this repo

> Source of truth: `PRD.md` → `DESIGN.md` → `ARCHITECTURE.md` → `DATABASE.md` → `API.md`, then this file. **If they disagree, the earlier document wins and you must flag the conflict instead of guessing.**

---

## 0. Non-negotiables (read before you touch anything)

1. **Inspect before you edit.** Read the file, `grep` for the exact string, and understand the surrounding markup before writing. Never blind-replace a pattern that appears more than once.
2. **The design system is closed.** New colour, new font, new shadow style, new radius = requires approval (see `DESIGN.md`). Reuse `.btn`, `.chip`, `.tab`, `.pillar`, `.sheet`, `.stat`, `.tabout`.
3. **Bengali typesetting rules are load-bearing.** `line-height ≥ 1.5` on mono/small text; Bangla digits always in `--bn`; never `line-height:1` on a chip. Breaking this re-introduces the clipping bugs the owner reported three times.
4. **One file, one build.** The deployable must stay generated by `python3 _src/build.py`. No bundler, no framework, no `npm install`, no new dependency without written approval.
5. **Zero third-party requests at runtime.** No CDN, no Google Fonts link, no analytics script, no chat widget. Fonts and images are local.
6. **No secrets in the repo or the bundle.** No API keys, tokens, `.env` values, Vercel credentials.
7. **Never weaken the SEO contract.** Canonical, JSON-LD, one `<h1>`, `alt` text, `robots.txt`/`sitemap.xml`/`llms.txt` must survive any change.
8. **Never ship a console error.** Verify with Playwright `pageerror` + console listener.
9. **Keep `dist/` and `math-academy.html` in sync** with `_src/` — both are generated; regenerate, never hand-edit.
10. **Ask before doing anything on the "requires approval" list** (§9).

## 1. Code quality & naming

- **HTML:** semantic elements, `aria-*` where a custom widget is unavoidable, BEM-ish classes (`block__element--modifier`). Data attributes for JS hooks (`data-wa`, `data-ink`, `data-tool`, `data-filter`), never for styling.
- **CSS:** custom properties for tokens; one component = one block; media queries grouped at the end of the block; no `!important` except overriding a vendored/inline rule, and then with a comment saying why.
- **JS:** ES5-compatible syntax (the file is served as-is to cheap Android browsers); IIFE modules; `var`/`function` style consistent with the file; early returns; no global leakage except `window.WA_NUMBER`-style constants if required.
- **Naming:** Bengali for user-visible content, English for code. File names: `02-top.html`, `03-sections.html`, `04-bottom.html`, `site.css`, `site.js` (keep the numeric prefixes).
- **Comments:** explain *why*, in English, one line. Bengali comments allowed for copy decisions aimed at the owner.
- **No dead code.** If you remove a feature, remove its CSS and JS in the same edit.

## 2. Project structure

- Edit **only** inside `_src/` (plus `docs/`, `ai/`, `assets/`, root static files).
- Never create a new top-level directory without approval. Never add a build tool config (`package.json`, `vite.config`, `tailwind.config`) — the absence is the architecture.
- `dist/` is output. `uploads/` is raw input (do not delete).

## 3. Component reuse

- Before styling anything new: search `site.css` for an existing block that already does it (`grep -n "\.card\|\.pillar\|\.sheet\|\.chip\|\.tab"`).
- A new visual variant = a modifier on an existing block, not a new block.
- Copy patterns: user-facing Bengali copy follows `DESIGN.md` §13 voice (no superlatives, no promises of marks).

## 4. Dependencies

- Runtime dependencies allowed: **none** beyond the vendored `gsap.min.js` (keep its header intact).
- Build dependencies allowed: **Python 3 standard library only.**
- Dev tooling (Playwright, Lighthouse) is *operator-only* and must not appear in the repo as a required dependency.
- Adding anything requires: written justification, bundle-size impact, and owner approval.

## 5. Type safety

No TypeScript by design. Compensate with:
- defensive reads (`if (!el) return;`), no implicit globals
- `'use strict'` at the top of each IIFE
- number parsing with explicit fallbacks (`+value || 0`)
- DOM queries that assume nothing about node existence

## 6. Error handling

- Every DOM block starts by checking its root element.
- No empty `catch`. If a failure is expected, comment why it is swallowed.
- Never let an enhancement break the base page: if GSAP fails, the preloader timer path must still work; if JS is disabled, every link must already be valid HTML.
- Form validation errors: Bengali message, `aria-invalid`, focus moved to the field, never a `alert()`.

## 7. Security & secrets

- `grep -rn "secret\|api_key\|token\|password" dist/` must return nothing.
- All outbound links: `rel="noopener"` (and `noreferrer` for untrusted).
- Render user-influenced values with `textContent`, never `innerHTML`.
- The booking form must never POST anywhere. If a backend is ever approved, authorization happens server-side, never in the browser.
- Do not add `target="_blank"` without `rel="noopener"`.

## 8. Database / API access

- There is no database and no API. Do not invent one.
- If a future task requires them, follow `DATABASE.md` §8 and `API.md` §3 exactly, and open with a proposal before writing code.

## 9. Requires explicit owner approval

| Change | Why it needs approval |
|---|---|
| Any new dependency, framework, or build step | architecture |
| Changing the WhatsApp number, fees, seat counts, batch schedule | business truth |
| Publishing the school affiliation, real student names, or real results | privacy / employment |
| Deleting a section or a CTA | conversion |
| Changing the colour tokens, fonts, or the type scale | design system |
| Adding analytics, cookies, pixels, or any third-party script | privacy + performance |

## 11. Documentation discipline

- Any change to tokens, sections, IDs, data shape, or SEO → update `_src/SPEC-COMMENT.html`, `README.md`, and the affected `docs/*.md` **in the same change**.
- Record the change in `ai/decisions.md` (why) and, if it is a bug, in `ai/known-issues.md`.
- Keep `ai/current-state.md` truthful — it describes reality, not intentions.

## 12. Git / change discipline

- One logical change per commit; message format: `type(scope): imperative summary` (`fix(hero): keep ১ intact at 10px`, `feat(seo): add llms.txt`).
- Never commit `dist/` unless the deploy method requires it (documented in `docs/DEPLOY-VERCEL.md`).
- Never commit `uploads/` originals if they contain unpublished people; ask first.
- No unrelated drive-by formatting. No reordering of unrelated lines.

## 14. Anti-patterns that already burned us (do not repeat)

| Symptom | Cause | Correct approach |
|---|---|---|
| Headline glyphs clipped | `line-height: 1` or `overflow:hidden` with no bottom padding | 1.22 + `.22em` padding |
| Bangla "১" looks broken at 10 px | Latin-only font owning the digit | digits in `--bn`, mono only for Latin |
| Photo washed out by the ink reveal | SVG `feTurbulence`/`feDisplacementMap` on the mask | layered CSS `mask-image` with hard stops |
| Reveal looks like a plain circle | one radial gradient | 4 lobes with different easing |
| Number text clipped in a chip | fixed height + tight line-height | `min-height`, `line-height ≥ 1.5` |
| Horizontal scroll on mobile | overflowing chip row | flex-wrap 2×2 at `< 600px` |
| CLS on font load | `font-display: swap` without metric overrides | `BN Metric` fallback + font gate |
| Console error | `page.click` on a hidden panel (test) or missing null-check (code) | tap the tab first / guard the root |
